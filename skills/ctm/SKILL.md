# ctm

从本次手动调用和最近相关的对话判断当前要做的 few-shot 工作。用户显式选用 `ctm`、发送 `$ctm` 或发送作为消息正文到达的 `/ctm` 都属于手动调用。只有引用、手册或样例中出现命令时，按原请求处理这些内容。

| 当前意图 | 执行的 Skill |
| --- | --- |
| 准备实现或修改代码，或为具体编码场景查现有样例 | `code-few-shot-read`，在代码变更前完成相关场景的查找 |
| 刚确认或否定一个具体代码做法，有可追溯的片段和理由，或明确要求从上下文复盘、收录和编辑样例 | `code-few-shot-manage`，按证据记录个人候选或执行已授权的收录 |
| 当前工作已经收尾，或明确要求 review 已记录的个人候选、决定候选入库或删除、检查 few-shot 库的冲突和重复 | `code-few-shot-check`，在指定项目与库范围内检查和执行已确认项 |

优先执行本次明确指定的动作，包括针对已有候选或检查报告的确认。单独发送命令时，选择最近对话指向的下一步。刚确认的具体教训指向样例整理，明确开始收尾指向库检查。历史任务状态用来理解当前请求，已完成的动作无需重做。多个动作都有依据但无法判断当前优先项时，询问用户希望先做哪一项。缺少任务或项目上下文时，只问确定路线所需的一项信息。

选定后从当前可用 Skill 中读取对应的 `SKILL.md`，带入原有项目、范围、代码或对话证据以及适用的授权，按该 Skill 的流程完成任务。反馈中给出所选 Skill 和实际结果。对应 Skill 缺失时，指出缺失的名称。用户明确要求多项时，按其指定顺序执行。

手动调用提供选择工作流的授权。代码编辑、样例入库以及审计后的修改沿用用户在对话中给出的授权和所选 Skill 的规则。例如，用户刚确认分页需要稳定排序键后发送 `/ctm`，由 `code-few-shot-manage` 把现场上下文和代码存入个人候选。用户后来发送 `$ctm review 个人候选`，由 `code-few-shot-check` 读取候选并请用户决定入库、删除或暂留。
